# Codex 백엔드 리뷰 2차 (2026-11-20): 출력 음소거, 체인 저장/복원

대상은 커밋되지 않은 Codex 변경이다. `src/audio/*`, `src/plugins/PluginChain.*`, `tests/*`, `docs/*.md` 11개 파일, +772/−90.

판정은 **수정 후 승인(Approve with fixes)**이다. Critical은 없다.
- **검증:** Debug와 Release 테스트 실행 파일이 59/59 통과했고 종료 코드는 0이다. Debug에서 assert나 누수 출력은 없었다.
- **1차 리뷰:** Important 1·2와 Minor 3~5가 모두 반영됐다.

## Important

### I1. 복원 중에도 `createStateXml()`이 동작해 일부만 담긴 체인을 돌려준다 (`PluginChain.cpp:275-291`)
- **문제 상황:** 실행 직후 자동 복원이 8개 중 3번째 플러그인을 만들고 있을 때 앱을 닫는다. 그러면 자동 저장이 2개짜리나 빈 체인을 써 버린다.
- **화면 쪽 대응(완료):** 화면은 `isRestoring()` 동안 자동 저장을 건너뛴다. 실행 시 복원에서 플러그인이 빠지면, 사용자가 체인을 직접 바꾸기 전까지 자동 저장을 멈춘다. 이전 파일은 `last-chain.prev.xml`로 백업한다.
- **백엔드 권장 수정:** 복원 중에는 `nullptr`을 돌려주거나, 원본 XML을 보관했다가 그것을 돌려준다. 어느 쪽으로 하든 문서에 적는다.

### I2. 신뢰할 수 없는 프리셋이 임의의 VST3 경로를 로드할 수 있다 (`PluginChain.cpp:321-331`, `410`)
- **문제:** XML의 `PLUGIN fileOrIdentifier`가 그대로 `createPluginInstanceAsync`에 들어간다. 그래서 스캐너 목록과 스캔 중 크래시로 걸러진 차단 목록을 우회한다.
- **지금 상황:** 프리셋은 앱이 직접 쓴 로컬 파일뿐이다. 가져오기 기능이 없어서 지금 당장은 위험이 낮다. 프리셋을 공유하거나 가져오는 기능을 넣기 전에는 반드시 고친다.
- **수정:** 스캐너의 `KnownPluginList`로 설명을 다시 찾아 확인한다(`createIdentifierString()` 또는 형식+uid). 목록에 없거나 차단된 것은 `failedNames`에 넣는다. 이렇게 하면 복원이 `loadCache()`보다 뒤에 와야 한다. 화면은 이미 그 순서다.

## Minor

1. **`audioDeviceError`가 치명적이지 않은 오류에도 처리를 멈춘다** (`AudioEngine.cpp:63`).
   - CoreAudio는 실패한 OSStatus를 모두 `audioDeviceError`로 보낸다. 장치는 계속 돌아가는데 출력만 무음이 된다. macOS에서만 생긴다.
   - **수정:** 메시지 스레드로 미룬 뒤 `!device->isPlaying()`일 때만 정지한다. 아니면 다시 준비한다.
2. **큰 상태 덩어리를 메시지 스레드에서 동기로 처리한다** (`PluginChain.cpp:330-331`, `421`).
   - `getAllSubText()`를 두 번 부르고, 디코드한 뒤 다시 인코드한다. 크기 상한이 없다.
   - 2GB를 넘으면 `(int)` 캐스트에서 잘린다. 플러그인 항목 수에도 상한이 없다.
   - **수정:** 서브텍스트를 한 번만 계산하고, 플러그인별 상태(예: 64MB)와 항목 수에 상한을 둔다.
3. **중첩 복원 거절 메시지가 망가진 파일 메시지와 같다** (`PluginChain.cpp:303`). 서로 다른 문구로 나눈다.
4. **복원 시작과 끝에 `onChanged`가 없다.** 지금 체인이 비어 있고 모든 생성이 실패하면 `onChanged`가 한 번도 오지 않는다. 화면은 `isRestoring()` 폴링과 `onDone`으로 대응했다. 시작과 끝에 `changed()`를 부르거나, `onDone`이 끝 신호라고 문서에 적는다.
5. **복원 중 생성 실패 이유를 버린다** (`PluginChain.cpp:412`). 이름만 `failedNames`로 오므로 화면이 실패 이유를 보여줄 수 없다.
6. **`ProcessorFactory`가 모든 형식에서 `formatManager`를 대체한다** (`PluginChain.cpp:170`). VST3가 아닌 형식에만 쓰는 대체 경로로 바꾸거나, 지금 동작을 문서에 적는다.
7. **빈 상태가 문서와 다르게 저장된다.** 빈 상태는 `<State/>`가 아니라 `<State></State>`로 저장된다. 파싱은 문제없다. 문서나 코드 중 하나를 고친다.
8. **테스트 공백:**
   - 중첩 복원 거절
   - 장치가 실행 중일 때 삭제 전에 `onChanged`가 오는지
   - 복원 전에 시작한 `addPlugin`이 복원 도중에 끝나는 경우
   - 장치 실행 중 복원할 때 클릭이 없는지
   - 음소거로 시작한 뒤 해제하면 페이드인되는지
   - `PluginChainTests.cpp:232`의 주석("empty State 포함")이 실제 테스트와 다르다.
   - `PluginChainTests.cpp:424`는 이동된(moved-from) `std::function`이 비어 있다고 가정한다. `pending`을 명시적으로 리셋한다.
9. **`ChainSlot.h:11-13` 주석이 오래됐다.** "엔진이 생명주기 콜백에서 슬롯을 준비할 수 있다"는 내용이 그대로 남아 있다.

## 화면 쪽 참고 (계약)

- **음소거:** 원자 변수라서 `initialise()` 전에도 안전하다. 시작 상태는 첫 샘플부터 적용되고, 전환할 때는 10ms 페이드가 걸린다. 출력 미터는 음소거가 적용된 뒤의 소리를 보여준다.
- **복원 중:** `addProcessor`/`remove`/`move`/`setBypassed`는 false를 돌려주고 `addPlugin`은 무시된다. 이때 `onError`는 오지 않으므로 화면이 컨트롤을 막아야 한다.
- **`onDone`:** 메시지 스레드에서 비동기로 정확히 한 번 호출된다. PluginChain이 먼저 파괴되면 호출되지 않는다. 컨트롤을 다시 켤 때는 이 신호를 쓴다.
- **복원 중 소리:** 플러그인을 하나씩 다시 만드는 동안 마이크가 효과 없이(dry) 나간다. 방송 중에 프리셋을 바꿀 때는 이 점을 감안해야 한다.
