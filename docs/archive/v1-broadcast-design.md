# 설계 문서: 방송용 마이크 VST3 체인 호스트 (기본 뼈대)

작성일: 2026-11-18
상태: 검토 반영 완료, 승인 대기

## 1. 의도

초보 방송인이 **마이크 소리에 VST3 플러그인(노이즈 제거, EQ, 컴프레서 등)을 걸어 실시간으로 방송에 내보내는** 데스크탑 앱이다.
이름은 "DAW"지만 타임라인이나 녹음 편집기가 아니라 **실시간 이펙트 체인 호스트**에 가깝다.

- 사용자: 오디오 지식이 적은 방송인. 오디오 인터페이스(오인페)는 갖고 있다.
- 신호 흐름: `마이크 → 오인페 입력 → [이 앱: 플러그인 체인] → 오인페 출력 → (오인페 루프백 등) → OBS`
- OBS로 소리를 넘기는 일은 **오인페가 맡는다**. 이 앱은 오인페 출력까지만 책임진다.

이번 작업은 **기본 뼈대**만 만든다. 구체적인 기능은 이후 사용자와 질문을 주고받으며 하나씩 정한다.

## 2. 목표 / 비목표 / 안티골

### 목표 (이번 뼈대에서 동작해야 하는 것)
1. 앱 창이 뜬다.
2. 오디오 장치(입력/출력 장치, 샘플레이트, 버퍼 크기)를 고를 수 있다.
3. 마이크 입력이 플러그인 체인을 거쳐 출력으로 나간다. 체인이 비어 있으면 그대로 통과한다.
4. 시스템의 VST3 플러그인을 스캔하고 목록으로 보여준다.
5. 체인에 플러그인을 **추가 / 삭제 / 순서 변경 / 바이패스**할 수 있다.
6. 체인에 넣은 플러그인의 **자체 편집 창**을 열 수 있다.
7. 입력 / 출력 레벨 미터가 있다.
8. 위 체인 조작을 **방송 중에 해도 클릭이나 끊김이 없다** (5.1 참고).
9. GitHub Actions로 **Windows와 Linux 빌드가 자동 확인**된다 (사용자 결정, 2026-11-18).

### 비목표 (이번 뼈대에서 하지 않는 것)
- 타임라인, 녹음, 오디오 파일 재생, MIDI
- OBS 연동, 가상 오디오 장치
- 앱 자체 내장 이펙트
- 여러 마이크 / 여러 트랙
- 체인 프리셋 저장/불러오기, 앱 종료 후 상태 복원 (구조만 고려하고 구현은 다음 단계)
- 초보자용 마법사, 추천 체인, 디자인 다듬기
- 플러그인 별도 프로세스 스캔(크래시 격리), 자동 업데이트, 설치 프로그램

### 안티골 (기술적으로 돌아가도 실패로 보는 것)
- 방송 중 소리가 끊기거나(글리치) 눈에 띄는 지연이 생긴다.
  → 오디오 스레드에서 메모리 할당, 잠금, 파일/UI 접근을 하지 않는다.
- 방송 중 플러그인 켜기/끄기, 추가, 삭제, 순서 변경 순간에 소리가 튀거나 멈춘다 (사용자 확인: 방송 중에도 전부 바꿀 수 있어야 함).
- 초보자가 화면을 보고 무엇을 눌러야 할지 모른다. 뼈대 단계에서도 화면 구성은 단순하게 유지한다.

## 3. 제약

- **언어 / 프레임워크: C++17 이상 + JUCE 8** (사용자 결정, 아래 접근법 참고)
- **빌드: CMake**. JUCE는 CMake `FetchContent`로 특정 태그를 고정해서 받아온다. 저장소에 JUCE를 복사해 넣지 않는다.
- **대상 OS: Windows가 주 사용 환경**이다. 개발은 현재 Linux(Ubuntu)에서 한다.
  - 같은 코드가 Windows / Linux / macOS에서 빌드되도록 OS 전용 코드는 쓰지 않는다.
  - Windows의 ASIO는 이번 뼈대에서 빌드 옵션 자리만 마련한다. 실제 활성화와 검증은 Windows 환경에서 다음 단계에 한다.
  - 이 Linux 머신에는 JUCE 빌드에 필요한 개발 패키지(ALSA, X11, freetype 등)가 아직 없다. 빌드 검증 전에 `apt` 설치가 필요하다(관리자 권한, 사용자 확인 후 진행).
- **플러그인 형식: VST3만** 지원한다.
- **라이선스:** JUCE는 AGPLv3 또는 상용 라이선스이다. 판매 전에 상용 라이선스를 검토해야 한다(지금은 결정하지 않음).

## 4. 접근법

| | 방법 | 장점 | 단점 |
|---|---|---|---|
| **선택** | **C++ + JUCE** (체인 엔진은 직접 구현, 5.1) | VST3 호스팅(스캔, 로드, 편집 창, 상태 저장), 저지연 오디오 입출력(ASIO 포함), GUI를 한 프레임워크에서 제공하며 검증돼 있다 | C++ 메모리 안전성, JUCE 라이선스 |
| 탈락 | C++ + Steinberg VST3 SDK 직접 + RtAudio + Qt | 라이선스 부담이 적고 제어 자유도가 높다 | JUCE가 해주는 일을 전부 직접 구현해야 해서 뼈대에만 몇 배의 시간이 든다 |
| 탈락 | Rust (+ C++ 엔진 FFI) | 처음 원했던 언어 | Rust의 VST3 호스팅 생태계가 미성숙하고, FFI를 섞으면 복잡도만 늘어난다 |

처음에는 Rust를 원했지만, VST3 호스팅이 잘 갖춰진 언어로 바꾸기로 하고 JUCE를 골랐다(2026-11-18 대화).
이유: 이 앱의 핵심은 "VST3를 안정적으로 걸고, 지연 없이 소리를 내는 것"이다. 그 부분을 검증된 코드에 맡기고, 개발 시간은 초보자용 화면과 흐름에 쓴다.

## 5. 구조

### 5.1 오디오 처리

**사용자 결정 (2026-11-18):** 방송 중에도 켜기/끄기, 추가, 삭제, 순서 변경을 **전부** 할 수 있어야 하고, 그때 틱 소리나 끊김이 없어야 한다.
그래서 `AudioProcessorGraph`는 쓰지 않는다. 그래프 재연결과 노드 bypass는 두 블록 사이에서 신호를 뚝 끊어 바꾸므로 클릭이 난다. 대신 **직접 만든 체인 엔진**을 쓴다.

- `juce::AudioDeviceManager`로 장치를 열고, `AudioEngine`이 `juce::AudioIODeviceCallback`을 직접 구현한다.
- **체인 = 슬롯 배열.** 슬롯 하나는 다음으로 이루어진다.
  - 플러그인 인스턴스
  - wet/dry 게인 스무더(`juce::SmoothedValue`)
  - 그 플러그인의 지연만큼 늦춘 dry 신호용 딜레이 라인
- **바이패스:** 플러그인 자체 bypass 대신, 슬롯의 wet → dry 크로스페이드(기본 약 20ms)로 한다.
  - dry 신호는 플러그인 지연만큼 늦춰서 섞는다. 그래야 섞는 동안 소리가 겹쳐 울리지(콤 필터) 않는다.
  - 바이패스 상태에서도 플러그인은 계속 처리한다. 다시 켤 때 상태가 끊기지 않게 하기 위해서다.
- **구조 변경은 해당 슬롯이 완전히 dry일 때만 한다.**
  - **추가:** 새 슬롯을 dry 상태로 끼워 넣은 뒤 wet으로 페이드인한다.
  - **삭제:** dry로 페이드아웃이 끝난 뒤 빼낸다.
  - **순서 변경:** 옮길 슬롯을 dry로 페이드 → 위치 이동 → wet으로 페이드인.
    - 순간적으로 그 이펙트가 빠졌다가 돌아오지만 클릭은 없다.
- **총 지연이 바뀌는 변경**(지연 있는 플러그인 추가/삭제)은 출력 전체를 짧게(약 10ms) 페이드아웃 → 적용 → 페이드인한다. 지연 길이가 갑자기 바뀌면서 생기는 튐을 막기 위해서다.
- **스레드 규칙**
  - 플러그인 생성과 `prepareToPlay`는 오디오 스레드 밖에서 한다(`createPluginInstanceAsync`).
  - UI → 오디오 스레드 명령은 락프리 큐로 전달한다.
  - 다 쓴 슬롯과 인스턴스는 다시 큐로 메시지 스레드에 돌려보내 거기서 해제한다. 오디오 스레드는 메모리를 할당하거나 해제하지 않는다.
  - 슬롯 배열 최대 크기(예: 16)는 미리 확보해 둔다.
- **채널 처리 (내 결정):** 마이크는 보통 모노이므로, 선택한 입력 채널 1개를 받아 **스테레오(L/R 동일)로 복제한 뒤** 체인에 넣는다. 출력은 스테레오. 대부분의 방송용 플러그인이 스테레오를 전제로 하기 때문이다.
- 레벨 미터: 체인 앞뒤에서 피크 값을 원자 변수(`std::atomic<float>`)로 기록하고, UI가 타이머로 읽어서 그린다.

### 5.2 플러그인 관리

- `juce::AudioPluginFormatManager`(VST3만 등록) + `juce::KnownPluginList`
- 스캔 결과는 사용자 앱 데이터 폴더에 XML로 캐시한다. 앱 시작 시 캐시를 읽고, 사용자가 "다시 스캔"을 누를 때만 스캔한다.
- 스캔은 이번 뼈대에서는 같은 프로세스에서 하고, UI가 멈추지 않도록 백그라운드에서 진행한다. 크래시 격리(별도 프로세스 스캔)는 다음 단계로 미룬다.
- 플러그인 편집 창: 플러그인의 `createEditorIfNeeded()`를 별도의 `DocumentWindow`에 띄운다. 플러그인을 체인에서 지우면 창도 닫는다.

### 5.3 화면 (뼈대 수준)

창 하나에 아래 요소만 둔다.

```
┌──────────────────────────────────────────────┐
│ [오디오 설정]                    입력 ▮▮▮▯▯  │
│──────────────────────────────────────────────│
│  1. ReaFIR        [켜짐] [편집] [↑][↓] [삭제] │
│  2. ReaComp       [켜짐] [편집] [↑][↓] [삭제] │
│                                              │
│  [+ 플러그인 추가]                            │
│──────────────────────────────────────────────│
│ [플러그인 다시 스캔]             출력 ▮▮▯▯▯  │
└──────────────────────────────────────────────┘
```

- "오디오 설정"은 JUCE 기본 `AudioDeviceSelectorComponent`를 대화상자로 띄운다(뼈대 단계).
- "플러그인 추가"는 스캔된 목록에서 고르는 팝업 메뉴이다.
- **UI 문구는 한국어 (내 결정).** 대상이 한국 방송인이라고 보았다. 한글 폰트 표시를 위해 OS별 기본 한글 폰트를 지정한다.
- 순서 변경은 뼈대에서는 ↑/↓ 버튼으로 한다. 드래그는 다음 단계로 미룬다.

### 5.5 검증 방법

- Linux에서 빌드가 성공한다(경고 수준은 JUCE 권장 설정을 따른다).
- 앱이 실행되어 창이 뜨고, 오디오 설정 대화상자에서 장치를 고를 수 있다.
- 체인이 비어 있을 때 입력이 출력으로 통과하고, 미터가 움직인다.
- 설치된 VST3가 있으면 스캔, 추가, 편집 창, 바이패스, 삭제가 동작한다.
- **현재 개발 머신 상태 (2026-11-18 확인):** VST3 플러그인이 하나도 없고, 화면(디스플레이) 없는 세션이다.
  - 따라서 이 머신에서는 **빌드 성공까지만** 검증한다. 실행과 플러그인 동작 검증은 사용자 PC에서 한다.
  - 테스트용 무료 Linux VST3가 필요하면 LSP Plugins(`lsp-plugins-vst3`)를 쓴다 (내 결정, 설치는 사용자 확인 후).
- 클릭 없음 검증: 플러그인 대신 쓸 **테스트용 내부 프로세서**(예: 게인 반전, 고정 지연 추가)로 사인파를 흘리며 바이패스/추가/삭제/순서 변경을 할 때, 출력 샘플 간 급격한 점프가 없는지 자동 테스트로 확인한다. 이 테스트는 화면과 VST3 없이도 돌아간다.
- **Windows:** GitHub Actions에서 빌드 성공을 확인한다.
  - 이 폴더는 아직 Git 저장소가 아니다. `git init`과 첫 커밋은 하지만, GitHub 저장소 생성과 push는 사용자 확인 후에 한다.
- 지연(레이턴시) 목표 수치는 이번 뼈대에서 정하지 않는다. Windows 저지연 경로(ASIO / WASAPI 독점 모드)와 함께 다음 단계에서 정한다.
