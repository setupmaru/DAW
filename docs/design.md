# 설계 문서: Pro Tools 스타일 DAW (v2)

작성일: 2026-11-22
상태: 첫 버전 구현 완료 (녹음·재생·편집 기본)

이전 버전(v1.0.1, 방송용 마이크 이펙트 체인)의 설계는 `docs/archive/`에 있습니다. v2는 그 앱의 **클릭 없는 VST3 체인 엔진, 플러그인 스캐너, ASIO 장치 설정을 재사용**하고, 화면과 구조는 멀티트랙 DAW로 새로 만들었습니다.

## 1. 의도와 범위

Pro Tools처럼 **여러 오디오 트랙을 녹음하고, 타임라인에서 편집하고, 믹서에서 섞어 내보내는** 데스크톱 DAW.

### 이번 버전에 들어간 것
- 여러 오디오 트랙(최대 64), 트랙마다 입력(모노 1채널 또는 스테레오 쌍) 선택, R(녹음 준비) / I(입력 모니터) / S / M
- 트랜스포트: 재생/정지, 녹음, 처음으로, 반복 재생(선택 구간), 메트로놈, 템포
- 녹음: [R]로 준비한 트랙마다 WAV(24비트) 파일로 녹음, 왕복 지연 보정, 자동 입력 모니터링
- 편집 창: 마디|박·분:초 눈금자, 클립 파형, 확대/축소·스크롤
  - 도구: 트림 / 선택 / 잡기 (F6/F7/F8), 모드: 슬립 / 그리드 (F2/F4)
  - 클립 이동(트랙 사이 포함), Alt+끌기 복사, 끝 트림, 페이드 인/아웃, 분할, 복제, 삭제, 구간 삭제
  - 실행 취소/다시 실행 (클립 편집)
- 믹스 창: 트랙마다 VST3 인서트(최대 16, 화면에 8칸), 입력, 팬, R/I/S/M, 페이더, 스테레오 미터, 마스터 채널
- 플러그인 지연 보정(PDC)
- 세션 저장/열기(`.dawsession` + `Audio Files` 폴더), 오디오 가져오기(파일 대화상자, 끌어다 놓기)
- 믹스다운 내보내기(오프라인 렌더, WAV 24비트)

### 이번 버전에 없는 것 (다음 단계 후보)
- MIDI 트랙, 가상 악기, 피아노롤
- 오토메이션, 센드/버스(AUX), 그룹
- 클립 게인 핸들, 크로스페이드 자동 생성, 셔플/스팟 모드, 플레이리스트(테이크 목록)
- 디스크 스트리밍 재생 (지금은 클립 오디오를 메모리에 올림)
- 트랙 삭제·믹서 조작의 실행 취소

## 2. 구조

```
src/
├── audio/      (v1 재사용) ChainProcessor, ChainSlot, LockFreeQueue, LevelMeterSource
├── plugins/    (v1 재사용) PluginChain, PluginScanner, PluginEditorWindow
├── engine/     오디오 스레드 쪽
│   ├── AudioData     파일을 세션 샘플레이트로 디코딩해 메모리에 둔 오디오 + 파형 개요
│   ├── Clip          클립(값 타입)과 순수 편집 함수(분할·트림·구간 삭제·덮어쓰기 배치)
│   ├── TrackAudio    트랙 한 개의 인서트 체인, 페이더/팬/뮤트/솔로/암, 지연 보정, 미터
│   └── MixEngine     장치 콜백, 트랜스포트, 재생 스냅샷, 녹음, 메트로놈, 오프라인 렌더
├── session/    메시지 스레드 쪽 모델
│   ├── Session       트랙·클립·마스터·템포·실행 취소, 변경마다 재생 스냅샷 발행
│   ├── SessionFile   .dawsession 저장/열기, 오디오를 세션 폴더로 모으기
│   └── Bouncer       믹스다운 오프라인 렌더
└── ui/         편집 창(TrackHeader, TimelineView), 믹스 창(ChannelStrip), TransportBar, MeterBar
```

### 2.1 오디오 처리 (블록마다)

```
트랙마다: 클립(또는 준비된 트랙의 입력) → 인서트 체인 → 지연 보정 → 페이더·팬·뮤트/솔로 ─┐
마스터:   합 → 마스터 인서트 → 마스터 페이더 → (메트로놈) → 출력 1-2
```

- **스레드 규칙 (v1과 같음):** 오디오 콜백은 메모리 할당·해제, 잠금, 로그, 파일 접근을 하지 않는다.
- **재생 스냅샷:** 메시지 스레드가 세션이 바뀔 때마다 `PlaybackSnapshot`(트랙별 클립을 원시 포인터로 평탄화)을 만들어 원자 포인터로 넘긴다. 오디오 스레드는 블록 시작에 최신 것을 가져가고, 다 쓴 것은 락프리 큐로 돌려보내 메시지 스레드가 지운다. 스냅샷은 `shared_ptr`로 오디오 데이터와 `TrackAudio`를 붙잡고 있어서, 트랙을 지워도 오디오 스레드가 쓰는 동안은 살아 있다.
- **파라미터:** 페이더·팬·뮤트·솔로·암·입력은 원자 변수. 오디오 스레드가 블록마다 읽고 이득 변화를 10 ms 동안 부드럽게 바꾼다(클릭 없음).
- **인서트:** 트랙마다 v1의 `ChainProcessor`를 그대로 쓴다. 추가·삭제·순서 변경·바이패스가 재생 중에도 클릭 없이 된다.
- **지연 보정(PDC):** 트랙별 체인 지연의 최댓값에 맞춰 나머지 트랙을 링 버퍼로 늦춘다(최대 32768샘플). 보정값이 바뀔 때는 마스터를 10 ms 동안 0으로 내린 뒤 바꾸고, 늘어난 지연만큼 무음을 유지한 다음 다시 올린다.
- **입력 모니터링:** 준비(R)된 트랙은 정지 중과 녹음 중에는 입력을, 일반 재생 중에는 클립을 들려준다(자동 입력). 트랙의 [I](입력 모니터)를 켜면 R이나 재생 상태와 상관없이 항상 입력을 들려준다(Pro Tools의 TrackInput).
- **팬:** 밸런스 방식(가운데에서 양쪽 0 dB, 한쪽 끝에서 반대쪽 무음).
- **클립:** 한 트랙에서 같은 시점에는 클립이 하나만 있다(테이프 트랙처럼). 클립을 놓으면 그 아래 부분을 덮어쓴다. 페이드는 선형.

### 2.2 녹음

- 메시지 스레드가 준비된 트랙마다 WAV 작성기(`ThreadedWriter`, 백그라운드 스레드)를 만들어 `RecordJob`으로 엔진에 넘긴다. 오디오 스레드는 작성기의 FIFO에 쓰기만 한다.
- 정지하면 오디오 스레드가 작업을 큐로 돌려주고, 메시지 스레드가 파일을 닫아 읽어 들인 뒤 클립으로 놓는다(실행 취소 한 단계 "녹음").
- **지연 보정:** 장치 입력+출력 지연과 믹스 지연을 합한 만큼 파일 앞부분을 건너뛰어, 녹음이 들은 소리와 맞게 놓인다.
- 저장한 적 없는 세션의 녹음은 사용자 앱 데이터의 `DAW/Unsaved Recordings`에 쓰고, 저장할 때 세션 폴더로 옮긴다.

### 2.3 세션 파일

```
<세션 이름>/
├── <세션 이름>.dawsession     XML: 템포, 샘플레이트, 트랙(이름·색·믹서·입력·클립·인서트 상태), 마스터
└── Audio Files/               녹음과 가져온 오디오
```

- 저장할 때 세션 폴더 밖의 오디오는 `Audio Files`로 복사한다(같은 파일은 한 번만). 그래서 세션 폴더째 옮겨도 열린다.
- 인서트 플러그인 상태는 v1의 `DAWChain` 형식(플러그인 설명 + base64 상태)을 그대로 쓴다.
- 열 때 장치 샘플레이트를 세션에 맞추려고 시도한다. 맞출 수 없으면 아래 상태 줄에 경고를 띄운다.
- 임시 파일에 쓴 뒤 바꿔치기해서, 저장이 실패해도 이전 파일은 남는다.

### 2.4 화면

- 메뉴: 파일 / 편집 / 트랙 / 재생 / 보기 / 설정. 모든 동작은 `ApplicationCommandManager` 명령이라 메뉴·단축키·버튼이 같게 동작한다.
- 트랜스포트 바: 모드·그리드 | 도구 | 트랜스포트 | 카운터(눌러서 마디|박 ↔ 분:초) | 선택 구간 | BPM | 확대·축소 | 편집/믹스
- 편집 창은 드래그하는 동안 클립을 실시간으로 바꾸고, 마우스를 놓을 때 실행 취소 한 단계로 기록한다.
- 한글 글꼴: Windows는 맑은 고딕, macOS는 Apple SD Gothic Neo, Linux는 설치된 한글 글꼴 중 첫 번째.

## 3. 검증

- 자동 테스트(`ctest`): 체인 엔진(v1), 클립 편집 함수, 믹스 엔진(재생 위치·페이드·뮤트/솔로/팬·루프·입력 모니터링·스냅샷 교체·녹음·PDC 정렬), 세션(편집·실행 취소·저장/열기 왕복·바운스 정렬), 타임라인 마우스 편집(이동·그리드·트랙 이동·Alt 복사·트림·페이드·구간 선택·눈금자).
- 화면: Linux Xvfb에서 `--screenshot <png> [--mix]` 옵션으로 창을 그려 확인.
- 실제 오디오 인터페이스와 VST3 플러그인으로 듣는 검증은 사용자 PC에서 해야 한다.

## 4. 내린 결정 (되돌릴 수 있음)

- 클립 오디오를 메모리에 올린다. 구현이 단순하고 오디오 스레드가 디스크를 기다리지 않는다. 대신 긴 세션은 메모리를 많이 쓴다(48 kHz 스테레오 1분 ≈ 23 MB). 다음 단계에서 디스크 스트리밍으로 바꿀 수 있다.
- 한 트랙의 클립은 겹치지 않는다(덮어쓰기). Pro Tools의 기본 동작과 같고 렌더링이 단순하다.
- 샘플레이트 변환은 Lagrange 보간. 고품질 변환은 다음 단계.
- 팬은 밸런스 방식. 모노 트랙용 팬 법칙(-3 dB 등)은 다음 단계.
- 메트로놈은 출력에만 섞이고 녹음·바운스에는 들어가지 않는다.
